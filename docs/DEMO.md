# 可复现的授权素材演示

演示从空库开始，使用首页提供的 MDN CC0 花朵视频，或你自己的可公开素材。不能用客户素材冒充公开示例，也不要为了截图注入虚构任务、收入或用户。步骤是否已经在当前版本通过，须看 [VERIFICATION](VERIFICATION.md)；本文是操作脚本，不是执行结果。

## 准备与来源

按 [DEPLOYMENT](DEPLOYMENT.md) 启动三个服务，访问 `http://localhost:8090`。不要清空现有库：需要空环境时部署到单独目录和独立卷，或在新实例演示。保留现有资料与 Cookie。

首页示例 URL：

```text
https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4
```

该路径标识 CC0 示例，演示前应再次打开来源检查当前内容和许可说明。外部链接可能失效，下载或解析失败时展示错误并换自有素材，不将失败隐藏成成功。路径名本身不能代替所有素材的授权核对。

## 一次真实素材交付

| 步骤 | 操作 | 应观察的结果 |
| --- | --- | --- |
| 1 | 首页填入示例，元信息预览，再选日常预设下载 | 出现实际任务、解析元信息与进度，完成后可播放 |
| 2 | 再次添加相同链接和预设 | 明确显示重复跳过；没有第二份假数据 |
| 3 | 创建项目「公开示例交付」，客户填「演示客户」，预算 ¥0，备注写「公开演示，不对应真实交易」 | 项目可刷新读回，预算没有变成收入 |
| 4 | 管理素材，将刚下载的素材加入 | 显示真实素材和授权缺项，ZIP 尚不可交付 |
| 5 | 打开授权记录，选择 CC0，记录实际核对过的来源，勾选人工核对 | 就绪检查重算；若文件或资料还有问题仍显示缺项 |
| 6 | 导出 JSON/Markdown 清单，再下载 ZIP | 文档包含项目、来源与授权；ZIP 包含实际媒体和清单 |
| 7 | 解压到单独演示目录，播放素材并比对来源 | 媒体内容与库中素材一致，包内没有其他项目素材或绝对路径 |
| 8 | 标记已交付，再刷新 | 状态保留，仍能检查清单；这是人工状态标记，不代表客户验收或到账 |

可选失败演示：准备另一个未核对的素材，加入尚未交付的项目，观察交付被阻止。不要破坏主库文件来模拟失败；文件缺失等反例使用自动化隔离夹具。

## 字幕来源与知识闭环

花朵视频并没有下面的课程字幕。下列 SRT 是**人工编写的演示文本**，用于时间解析与知识功能验证，不声称与视频声音或画面同步。将字幕名标为「自编功能验证字幕」。素材太短时仅用前两秒作标记，避免超出实际时长。

```srt
1
00:00:00,000 --> 00:00:01,000
SQLite transactions protect a consistent task queue.

2
00:00:01,000 --> 00:00:02,000
素材交付之前，需要核对来源授权与署名要求。
```

1. 在学习页选中素材，导入以上字幕，并明确来源为自编演示。使用本地原句提取，不需付费模型密钥。
2. 搜索 `SQLite` 或 `来源授权`，核对返回原句、任务与字幕时间点。纯 TXT 导入没有时间轴时，不能期待虚构的时间点。
3. 建立 1.0 秒标记，标签为「核对来源」，备注为「此时点仅验证标记功能」。刷新后读回；删除仅删除标记，不删媒体。
4. 提取原句复习卡，查看填空与原句。选择页面上的「还没记住 / 基本记住 / 轻松记住」，分别对应 `again/good/easy`；首次到期分别为 10 分钟、1 天、4 天。同一天再次评价已未到期的卡片会被拒绝。该规则是简单调度，不声称使用 Anki 或研究验证的学习算法。
5. 导出内容制作简报，核对来源链接、原句要点、笔记与时间标记。当前简报是本地材料编排，发布文案与事实需要人工复核。
6. 将演示字幕改为另一段自编文本，再查看搜索与自动卡片，确认派生资料不会伪称来自旧字幕。手工卡片与自动卡片的处理规则以 API 与测试为准。

DeepSeek 摘要属于另外的可选调用。启用前需要真实密钥和授权发送字幕；没有实际调用时只能说接口存在与本地路径可用，不能展示虚构的模型结果或账单。

## 可复用导入与复盘

在项目页保存一个工作流配方，例如「公开示例整理」：日常预设、默认收藏、标签 `公开演示`、限速 0。运行同一示例链接，观察重复跳过；如需要演示新增，使用另一条自有/CC0 链接或不同有效预设，不能通过绕过去重制造活跃数据。

打开业务分析页，解释项目总数、状态、预算、已完成/已核对素材和容量。操作记录应反映刚才真实动作。下载媒体时长不是人工工时节省，项目预算不是营业额。

时间价值估算使用「已完成媒体数 × 用户输入的每份手工分钟数 ÷ 60」，人工价值再乘用户输入时薪。页面默认值只是便于试算的假设，不是测得的节省；实际效益应按 [BUSINESS](BUSINESS.md) 的对照计时方法验证。

## 演示证据包

记录当前完整 commit、日期时区、启动方法、输入来源、预设与网络情况，保存脱敏截图或视频。交付包可包含公开素材，但公开前再核对许可与清单中的个人信息。命令输出、失败反馈和文件比较应一并保存。

可按以下命令验证构建和回归，真实结果写入验收报告：

```bash
cd backend
python -m pytest -q
python -m ruff check app tests
cd ../frontend
npm run build
npm run test:e2e
```

浏览器测试需要相应服务与浏览器可用。执行前查看当前 Playwright 配置；测试命令成功也不表示上述每个手工演示步骤都已执行，覆盖范围须写清楚。
