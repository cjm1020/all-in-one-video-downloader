## 12 分钟评审演示

1. 2 分钟：说明目标用户、替代工作流和待验证商业假设，指出预算与收入的差别。
2. 4 分钟：使用自有或公开授权素材创建项目，展示缺失授权阻止交付，再补齐记录，下载 ZIP 并检查文件与清单。
3. 2 分钟：搜索自编示例字幕，定位标记并建立卡片，说明本地来源提取与外部 AI 模式的区别。
4. 2 分钟：展示一个有意义的失败用例，如文件缺失、任务冲突或来源变更后的卡片失效，并展示相应测试。
5. 2 分钟：讲解 T02/T10/T11 任一任务的独立验收方法，交代未完成的多用户与付费调用验证。

逐步脚本见 [DEMO](DEMO.md)。评审者应能检查失败路径；只展示顺利截图无法体现任务设计深度。

## 提交历史如何成为证据

保持实际功能、测试和文档变更形成自然提交，不重写时间、不创建空提交、不将同一功能机械切碎。用户要求至少 50 条提交是交付约束，不是专家资格，也不是社区热度。

```bash
git rev-list --count HEAD
git log --date=iso-strict --format='%h %ad %s'
git show --stat <commit>
```

选择几个重要提交解释需求、风险和验证：例如授权门禁、ZIP 交付、字幕失效、状态竞态和评估规范。每条应有可审查文件变化和独立目的。
